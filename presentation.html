Historical Context · 1993 vs Prior Art

The Memory Bus Was the Bottleneck: Code to the Data

In 1993, workstation CPUs (like the 28.5 MHz SPARCstation 2) were outpacing system bus memory bandwidth. Sun's existing capture mechanism, NIT (Network Interface Tap), copied every packet across the memory bus before userland filters could discard it.

McCanne and Jacobson formulated the core principle that defines packet processing today: discard unwanted packets in-place inside the kernel interrupt context without touching unnecessary memory words.

USENIX '93 Thesis (L90-93) "The packet should be filtered 'in place' ... if the packet is not accepted, only those bytes that were needed by the filtering process are referenced."
1. Sun NIT (Copy-First Model) High Bus Overhead
NIC Buffer → Copy 100% to Kernel Queue → Copy to User → Discard in Userland
2. CMU/Stanford CSPF (Stack Machine) Push/Pop Tax
In-Kernel → Stack Memory Push/Pop → Inefficient Short-Circuit Evaluation
3. BSD BPF (Register-Based Machine) Direct Accumulator Jump
NIC Buffer → Register Evaluation (A, X) → Zero Copy on Reject → Drop

Key Verification Discovery

Source-Level "Unsafe" ≠ Verifier Rejected

In Variant A, we deliberately deleted the NULL check following bpf_map_lookup_elem. Surprisingly, the verifier accepted the program (exit code 0).

0: (85) call bpf_map_lookup_elem#1
1: R0=map_value(map=counter,ks=4,vs=8)
→ Typed as PTR_TO_MAP_VALUE (provably non-null)
The Explanation: For BPF_MAP_TYPE_ARRAY with a constant in-range key, the kernel verifier statically inlines the lookup address at load time. The verifier semantically proved the pointer could never be NULL, rendering a source-level check redundant.

Statistical Audit · Why Per-Byte Slopes Fail to Separate

Why Nanosecond Slopes Drown: 35 Microseconds vs 15 Nanoseconds

Memory Copy Physics: 1993 vs 2026

In 1993, copying a 1500-byte frame over a 40 MB/s bus took ~37,500 nanoseconds (37.5 μs). This dwarfed all fixed per-packet overheads, creating an unmistakably steep linear slope ($R^2 \approx 0.99$).

On modern hardware with L1/L2 cache bandwidth exceeding 100 GB/s, copying 1500 bytes takes < 15 nanoseconds.

Meanwhile, kernel entry/exit, socket buffer allocations, and virtualization scheduling jitters have a variance of ± 2,000 to 5,000 nanoseconds.

// Signal-to-Noise Ratio
Signal (Memory Copy Delta): ~15 ns
Noise (VM Timer Resolution): ~3,000 ns
→ SNR = 1 : 200 (Noise Completely Dominates)
C2 Reject Slope: MIXED
A slope: -4.42 ns/byte, 95% CI [-9.19, +0.35]
B slope: -2.15 ns/byte, 95% CI [-6.95, +2.66]
Because Config A's slope CI crosses 0, the linear fit cannot mathematically rule out a flat slope for the copy-then-filter path.
C3 Accept Slope: INCONCLUSIVE ($R^2 \approx 0.01$)
Slope diff (A − B): -2.37 ns/byte, 95% CI [-10.9, +6.18]
Variance explained (R²): Config A = 0.8%, Config B = 2.1%
Packet size accounts for less than 2% of the variance. The linear model from 1993 is no longer the appropriate model on modern memory subsystems.

The Systems Engineering Paradox

The Pitfall of Hyper-Sensitive Canary Rules

Because the Phase 8.3 baseline was so pristine, the V8 canary threshold was calculated at an ultra-low canary_max = 0.010 CPU-s/s (less than 1% CPU).

During the intense 700k pps flood, legitimate softirq scheduling across the guest cores caused tiny blips of 0.014 CPU-s/s on Core 0. Rule V8 immediately flagged these as "contaminated", demonstrating how noise rules calibrated in quiet conditions can over-filter stress-test regimes.
