## 2. Matrix

| cfg | capture process | what it does with each packet |
|---|---|---|
| A | `build/baseline_sniffer` | kernel hands every packet to user space; copied whole, then filtered in user space (the paper's NIT role) |
| B | `build/loader -d` + port-4040 filter | kernel filter; matches queued, read and discarded (copy of matches only) (the paper's BPF role) |
| C | `build/loader` (no drain) + port-4040 filter | kernel filter, counters only, matches queue and overflow |
| D | `build/loader -d -p reject_all` | trivial kernel filter, nothing delivered: the **floor** |
| E | `build/loader -d -p accept_all` | trivial kernel filter, everything delivered and read |

Traffic: UDP via iperf3 from `p1veth0` (root namespace) to a server in namespace `p2ns`. Size is the L2 frame length without FCS; UDP payload = size - 42.
- **Reject curve (C2):** non-matching traffic (port 5050), configs A, B, D, sizes 64, 256, 512, 1024, 1500, fixed offered pps `P_curve`, R = 3.
- **Accept curve (C3):** matching traffic (port 4040), configs A, B, E, same sizes and `P_curve`, R = 3.
- **Flood (C4):** two unlimited UDP streams at once, port 4040 (matching) and port 5050 (noise), 256-byte frames, configs A, B, C, R = 5.
- **Warm-up:** one run per config at 512 bytes, discarded.
- **Calibration** fixes `P_curve` before the matrix: config A on non-matching traffic at 64 and 1500 bytes over the ladder 1000, 2000, 4000, 8000, 16000, 32000, 64000 pps for 5 s each; `P_curve = floor(0.5 x the lower of A's two loss-free ceilings / 100) x 100`. Calibration data is not result data.

Counts, from `bench.sh plan` (seed 20261018, `logs/p6_plan.log`; order frozen in `results/bench_plan.tsv`):

## 3. Per-run procedure (`bench.sh one`)

1. Servers: one-shot `iperf3 -s -J --logfile ... -1` per port inside `p2ns`, pinned to core 3.
2. Capture process started pinned to core 2, waited on until it prints `START`. For B to E the counter map is read with `bpftool -j map dump name p3_counters` (a stale pinned Phase 3 map is removed first; more than one map of that name flags the run).
3. `pidstat -p PID 1`, `pidstat -w -p PID 1` and `vmstat 1` start 1 s before traffic.
4. Snapshots of `/proc/stat` (per-CPU and `ctxt`) and `/proc/PID/stat` + `/proc/PID/status` before and after the traffic window.
5. iperf3 client(s) for 10 s (curve: one client on core 4 at the target rate, `-b = pps x payload x 8`; flood: two unlimited clients on cores 4 and 1), JSON output.
6. Counters read again, capture process stopped with SIGTERM (it reads `PACKET_STATISTICS` once), everything assembled into `logs/bench_<cfg>_<traffic>_<size>_<rep>.log` as `### sections`.
7. 3 s settle. Pinning: core 0 left free; capture 2; server 3; main client 4; noise client 1; never shared.

## 4. Metric definitions (all computed in `summarize.py`)

- `window` = difference of the two `/proc/stat` snapshot times (about 10 s). `clk` = `CLK_TCK` from each log header.
- `offered_pkts` = sum of the clients' `end.sum.packets`; `offered_pps = offered_pkts / window`.
- `tap_total`: packets the capture point saw. A: `kernel_packets` from the one `PACKET_STATISTICS` read; B to E: slot0 + slot1 deltas of the map. `matched`: A: its matched count; B to E: slot1 delta. `filter_dropped` = slot0 delta. `delivered`: B, D, E: the loader's `delivered_packets`; A: its matched count.
- **System-wide CPU** = sum over all CPUs of (user + nice + system + irq + softirq + steal) tick deltas / `clk` over the window.
- **Headline: system-wide CPU ns per matched packet** = system-wide CPU seconds x 1e9 / `matched`. Used for the accept curve and the flood. For the reject curve, where nothing matches, the same quantity per **offered** packet is used. It includes iperf3's own cost, which is common to all configs.
- **Floor**: mean D cost per offered packet at the same size on non-matching traffic. **Over D** = config cost - floor, with an SE from the group sds.
- **Decomposition (config B)**: copy-to-user = B(matching) - B(non-matching); parse+reject = B(non-matching) - D; per packet, same size, combined SE.
- **Matched pps** = `matched / window`.
- **Secondary**: capture-process CPU % = (`utime + stime` delta of `/proc/PID/stat` / `clk`) / window x 100 (exact window); `pidstat` Average `%CPU`, `cswch/s`, `nvcswch/s` and `vmstat` `cs` are recorded in `runs.json` as the contract asks but are not used in verdicts (`pidstat` samples are not aligned to the window). Context switches/s: process = (voluntary + nonvoluntary) delta / window; system = `/proc/stat ctxt` delta / window.
- **Drop separation**: filter drops = slot0; socket drops = `kernel_drops` from `PACKET_STATISTICS` (queue overflow). Always separate columns.
- **Steal %** = steal CPU-seconds over all CPUs / (window x number of CPUs) x 100.
- **Fits**: OLS of ns per packet on frame size over all valid runs: slope (ns/byte), intercept (ns/packet), their standard errors; 95% Student-t intervals. R² is reported but is not a criterion.

## 5. Validity and verdict rules (pre-declared; constants in `scripts/summarize.py`)

Run validity. A run failing any rule is INCONCLUSIVE: it stays in `runs.json` with its reasons, is listed in `results/exclusions.md`, and is excluded from the tables.
- V1: iperf3 client exit 0 and client and server JSON parse.
- V2: the capture process printed its FINAL line; snapshots and counters readable.
- V3: curve and warm-up runs: offered pps within +-5% of the target.
- V4: curve runs, every config except C: socket drops <= 0.1% of packets that reached the socket.
- V5: conservation: |tap_total - offered_pkts| <= max(20, 0.5% x offered_pkts) (covers ARP/IPv6 and the iperf3 control connection).
- V6: measured window within dur - 1 s to dur + 2 s.
- V7 (D6.1 item 6): steal > 5% of capacity. If more than 20% of a config's measured runs are V7-excluded, that config is INCONCLUSIVE in every table and verdict.
A (cfg, traffic, size) point needs at least 2 valid reps, otherwise it is INCONCLUSIVE. This inherits the Phase 2 discipline: rules are stated before any run, and a failure is investigated, not accommodated by widening a rule.

Verdict rules (D6.1 item 7): shape and sign, with 95% confidence intervals only. No absolute comparison with 1993 numbers, no ratio without an interval.
- **C2** (non-matching traffic, system CPU per offered packet over the D floor, fit against size): SUPPORTED if the slope for A has a 95% CI entirely above 0 (user-space copy-then-filter grows with size) AND the slope for B has a 95% CI containing 0 (kernel filter flat); NOT SUPPORTED if A's CI does not exclude 0 from above; otherwise MIXED. The D floor's own slope is reported (it reflects generator and veth size dependence and is removed by the subtraction).
- **C3** (matching traffic, system CPU per matched packet, fit against size): SUPPORTED if the slope CIs for both A and B lie above 0 AND the difference intercept(A) - intercept(B) has a 95% CI above 0 (A's fixed per-packet cost is above B's); MIXED if only some of these hold; NOT SUPPORTED if neither slope CI is above 0. Slopes and intercepts are reported with their CIs; E is shown as the accept-all comparator.
- **C4** (flood): SUPPORTED if the Welch 95% CI of the matched-pps ceiling difference (B - A) is above 0 AND the delta-method 95% CI of the factor (CPU per matched packet of A) / (that of B) is above 1; NOT SUPPORTED if neither holds; otherwise MIXED. If A is not saturated (socket drops <= 1% of packets reaching it), its figure is offered-load-limited and is reported as such. C4's CSPF ratio is not replicated end-to-end.

## 7. Findings from design, as ruled

1. **`/proc/net/packet` has no Drops column.** Header on this machine:
   ```
   $ head -1 /proc/net/packet
sk               RefCnt Type Proto  Iface R Rmem   User   Inode
   ```
   (`results/topology.md`). Ruling D6.1 item 1: `PACKET_STATISTICS`, one read per run at teardown.
2. **`pidstat` cannot see the kernel filter's cost.** For a veth pair the receive path, and so the filter, normally runs in softirq on the sending core (core 4), not in the capture process (core 2); that is ASSUMED, not verified. Hence the system-wide headline metric (D6.1 item 2). The per-CPU busy times are in each log, so the assumption can be checked from the data.
3. **Environment limits.** No CPU-frequency governor on this machine (`results/topology.md`), 5 cores shared with the desktop session, veth rather than a physical NIC, a virtual machine: run-to-run noise is expected, which is why the rules are written in terms of reps and CIs, with the steal rule as a guard.
4. **iperf3 limits.** At 64-byte frames the generator may not reach the target pps (rule V3 and calibration show it); the flood frame size (256 bytes) is a design choice: small enough to stress per-packet costs, large enough for iperf3 to generate it.
5. **Copy parity.** A copies each frame into a 128 KiB buffer with `recvfrom`; B, D and E drain with `recvfrom` into a 128 KiB buffer, so per delivered byte the copy is the same code path; they differ in how many packets reach it.

## 8. Wall-clock estimate

From `bench.sh plan` above: 110 runs x (10 s + 8 s overhead) = 33.0 min, plus calibration 14 runs x (5 s + 8 s) = 3.0 min: about 36 minutes of execution plus the smoke runs. The 8 s per-run overhead is ASSUMED and is replaced by the measured value after the smoke runs.

## 9. Execution order (after the pre-registration commit)

1. **Smoke**: `bench.sh one` once per config A to E (`BENCH_LABEL=smoke`, 5 s, 512-byte matching traffic at 2000 pps), parsed by `summarize.py smoke` into `results/smoke.md`. Labelled SMOKE and excluded from analysis (pre-declared). Only harness bugs are fixed from it; no threshold is tuned.
2. **Calibrate**: `bench.sh calibrate` -> `results/calibration.json`; the chosen offered pps is recorded in `logs/`. Not result data.
3. **Matrix**: `bench.sh run` (110-run plan, seed 20261018).
4. `summarize.py` -> `results/summary.md`; every excluded run listed with its rule in `results/exclusions.md`.
5. `results/verdicts.md`: DRAFT verdicts for C2, C3, C4 only, each citing the summary tables and the exclusions. Then stop for the reviewer.
